# 后续远程实验规范：冻结 OpenVLA，改变实际策略输入

本文件是实现与验收规格，**不是已完成的 GPU 集成代码或实验结果**。当前 NPZ 不包含图像、相机参数、动作、初始状态与任务元数据，不能从中直接生成可信的闭环成功率实验。CPU 无 GPU 阶段先完成；不重训 OpenVLA。

## A. 采集与配对

1. 记录 OpenVLA/LIBERO/robosuite/MuJoCo commit、权重标识、预处理/center crop、unnorm_key、动作归一化、随机种子、task_id、initial_state_id、环境重置方式、时间对齐、相机参数。已有79步仅作为开发轨迹。
2. 在学校分配的 GPU 作业内用冻结 checkpoint 采集多条独立 rollout，保存 RGB、实际可用的深度（若部署没有深度则不得假用）、eef pose、gripper_qpos、时间戳、动作和任务结果。ground truth object pose/contact/success 可由隔离评价进程保存，不传在线模块。成功与接触标签来源明确，评价文件不能成为预测输入。
3. 按 episode/initial state 分组划分标定、验证、测试；验证集决定阈值、mask 条件、补偿风格和不确定时的策略，再锁定。实验表在测试前确定。先小批量试点，再按配对成功率差异的区间精度规划规模，禁止将重复种子当独立轨迹。
4. 离线 M0/M1/M2 共用相同日志与人工遮挡条件。闭环按相同初始状态/种子/任务、遮挡时刻、固定遮挡区域/长度配对；不同策略产生不同后续轨迹是预期现象，不能强迫它们共享未来真值轨迹。必要时采用同一预登记时刻的完整环境快照分叉，快照只供环境重置，不能暴露给策略。

## B. 视觉目标 mask 与实际可见感知

先实现独立模块，并审计所有模型可见摄像头：

- 用可见 RGB（及部署允许的深度）识别碗并估计姿态；记录置信度、时间戳、失败状态。对称碗的朝向存在不可观测性，必要时报告对称性处理后的旋转误差，并与当前原始 SE(3) 指标分开。不可见帧不得更新目标 pose。
- 推荐先用**预登记的固定屏幕遮挡区域与时间表**制造遮挡，覆盖预期目标工作区，所有方法相同。固定 ROI 不依据隐藏目标真值移动；记录遮挡是否实际覆盖目标，但评价标签不能反馈在线决策。
- 如果做跟随目标的 mask，位置只能来自最后可见图像与可观测量；要检查跟踪边界是否继续编码隐藏目标位置。不得使用每帧 simulator segmentation/body pose 生成“精确碗轮廓”再作为部署输入；轮廓本身会泄漏位置。真实物理遮挡是另一种可以另测的条件。
- 清除其他相机/缩略图/深度通道中仍可见的目标信息，明确哪些信息在真实设置中可用。算法本身可用 eef 与 gripper，但不要给没有这种输入通道的基础 OpenVLA 虚构 proprioception 功能。
- CPU 的可见 bowl ground truth 前缀必须替换为该视觉估计结果；保留“理想前缀”作为单列上界对照。

## C. 真实 policy interface

标准 OpenVLA 的 action utility 由图像和任务文本构造 processor 输入再调用 predict_action；仅往 obs 加一个 `predicted_bowl_pos` 字段未必被模型读取。远端 Codex 必须沿本地 checkout 查明调用路径，再接入实际图像输入。不得以日志误差改善代替策略输入改善。

建议先实现一个可审查的**图像补偿接口**，权重保持冻结：

```text
可用相机图像 -> 固定外源遮挡 -> masked_rgb
可见历史 -> M0/M1/M2 -> hypotheses (无 hidden truth)
masked_rgb + 预测位姿 + 可见期外观/相机标定
    -> compensate_rgb(...) -> 实际 processor 图像 -> predict_action -> env.step
```

补偿渲染使用同一套确定性方法：从最后可见 RGB/深度保存目标外观，利用相机标定和预测位姿投影到图像中。若只有单视角贴片，可先用投影中心和固定外观做近似，明确它不是真实新视角；不能从隐藏真值渲染出完整物体。若相机运动，必须用可测外参/eef 几何更新投影。遮挡区域背景、透明度、贴片风格在 M0/M1/M2 中一致。

先检查最后可见目标是否被固定 ROI 清除；不能留下旧碗又贴出新碗。允许另测标记点或文本提示，但必须单列，且它们对冻结模型是否有用是待验证问题。图片补偿可能引入分布偏移，不保证改善成功率。

M2 不确定时首个正式版本**不补偿，保持 masked_rgb**，保存双假设供审计；不平均两个位姿，不分别运行后用真实成功或目标误差择优。这个在线行为称为 `M2 + uncertain→masked`，与 CPU 报告中的部分定义状态预测指标区分。若要改为基于两假设动作一致性的决策，须另行实现、仅用实际策略输出判断，并在验证集锁定规则。

## D. 进入正式 GPU 实验前的验收

- 图像/processor spy 测试：确认 predict_action 实际收到的是补偿图像；更改估计 pose 必须按相机几何改变其输入。保存送入 processor 的图像和实际 pixel_values 摘要。输入改变不保证动作改变，应记录动作敏感性但不能据此调测试结果。
- 消融开关：补偿关闭时与 masked baseline 的实际模型输入逐元素一致；M0/M1/M2 共用同一预处理与补偿渲染代码，仅改变预测假设/门控；未遮挡 baseline 也同路径预处理。
- 无泄漏测试：保持 RGB遮挡观测和本体观测不变，离线篡改隐藏 object/contact/segmentation/派生状态，预测、补偿图像、processor 输入应不变。模型固定随机状态时，动作应不变。不能改模拟器物理状态后期待闭环动作永远相同，那会改变可用观测。
- 缓存/提示/观测白名单审计：在线模块不能收到 env 或完整原始 obs；不读取 ground truth 评价文件；遮挡后不刷新目标贴片/深度/姿态。
- 分别保存实际执行动作和模型原始动作，核实 runner 的动作归一化、夹爪方向等原逻辑未被补偿模块改变。
- 在学校获准的短 GPU 作业中跑少量 smoke episodes，检查冻结权重、正确 reset、mask 生效、补偿实际到达策略。CPU 测试通过并不代表这些接口已通过。

## E. 正式实验与报告

在学校**已分配**的 GPU 作业内执行冻结推理和闭环评估，按实际学校文档取得资源。检查 hostname/作业环境与分配，再加载模型；不凭 `nvidia-smi` 可见就认定获准，不在登录网关运行。无需训练、梯度或优化器；模型用 eval/inference 模式，固定 checkpoint 与支持的推理随机性设置。

方法至少包括：未遮挡 baseline、遮挡无补偿、M0 补偿、M1 补偿、`M2 + uncertain→masked`。可单列 privileged oracle 上界，但它不属于可部署方法，必须与主结果隔离并明确标识。加同风格无位置信息补偿对照，以区分物理推断与简单图像提示效应。

主指标是每个 task / 初始状态的真实任务成功率和相对遮挡 baseline 的配对差异；同时报告抓取失败、错误放置、碰撞/安全事件、延迟、遮挡覆盖率、M2 不确定比例。位置误差是辅助指标。按任务分层汇总，按独立 episode/初始状态做配对 bootstrap 或合适的配对成功率分析，报告样本数和区间，不用每帧误差替代任务成功。

真实感知、理想可见前缀、固定ROI与真实遮挡应分开报告。阈值、贴片参数或失败样本排除规则不能在最终测试结果出来后反复修改；若修改，使用新的独立测试集。
